# 超级预测法：概率化决策框架

> 基于 Philip E. Tetlock《Superforecasting: The Art and Science of Prediction》
> 适用场景：在不确定条件下做判断，把模糊问题拆成可检验的预测

## 触发词
- 超预测 / 超级预测 / 概率化决策 / 泰特洛克 / Tetlock / Brier score
- 费米化 / Fermi-izing / 贝叶斯更新 / Bayesian updating
- 校准度 / 区分度 / 布里尔分数
- 云状问题 / 参考类 / 外部视角

---

## 核心理念

**预测不是算命，是量化不确定性。**

超级预测者的核心习惯：
- **概率化思考**：不说"可能会发生"，说"有65%的概率"
- **主动开放心态**：主动寻找推翻自己假设的证据
- **智力谦逊**：承认不确定性，知道自己不知道什么
- **持续校准**：用Brier score给自己的预测打分，长期改进

## 方法一：费米化（Fermi-izing）

### 概念

把边界模糊、无法直接判定对错的**云状问题**拆成可操作、可检验的**小问题**。

源自物理学家恩里科·费米的估算方法。

### FDE场景转换

| 云状问题 | 费米化后的可检验问题 |
|---------|-------------------|
| "捷安高科这个客户能不能签下来？" | "未来30天内，白晓亮是否明确表示对飞书CRM方案有兴趣（概率__%）" |
| "牧唐信息会不会续费？" | "未来2周内，李白是否安排预算审批会议（概率__%）" |
| "AI场景规划书能不能过？" | "雁鸣哥审阅后提出修改意见少于3条的的概率（概率__%）" |
| "这家公司适合推荐飞书AI吗？" | "客户业务负责人能否在5分钟内说出3个具体业务痛点（概率__%）" |

### 费米化的四个步骤

**第一步：识别边界**
这个问题的模糊边界在哪？哪些是可测量、可验证的？
> 例："客户认可AI价值"→ 改为"客户是否已采购AI产品/有AI预算"
> 例："客户关系好" → 改为"过去30天内有两次以上沟通"

**第二步：拆成组件**
把大问题拆成可粗略估算的组件。
> 费米经典：芝加哥有多少位钢琴调音师？
> =（钢琴总数 × 每年调音次数）÷（调音师每年工作量）
> =（人口 × 拥有率）× 调音频率 ÷ 年工作量

**第三步：对每个组件给一个最佳估算**
有数据用数据，没数据用合理推测。宁可大致正确，不要精确错误。

**第四步：组合成总估算**
用简单数学把组件组合成整体判断。
> 如果要估算客户签约概率：
> P(签约) = P(需求真实) × P(有预算) × P(决策者支持) × P(方案匹配)

## 方法二：外部视角打底，内部视角微调

### 两步法

**1. 先找参考类（外部视角）**

问：历史上类似的情况，结局是怎样的？

> FDE案例：你想推飞书AI给一个已使用火山引擎的客户。
> 参考类：过去类似"已有竞品AI→推荐飞书AI"的案例中，成功的比例是多少？
> 外部视角（基础比率）：假定约为30%

**2. 再用特殊性调整（内部视角）**

问：这个具体案例在某些方面是否明显不同？

> 向上调整因素：牧唐70%员工来自字节（对飞书/字节生态天然亲近）+ 飞书已在使用中
> 向下调整因素：已签火山引擎年框 + 创始人关注ROI
> 调整后概率：外部30% + 向上15% - 向下10% → 估计35%

### 基础比率速查表（FDE场景）

| 场景 | 基础比率参考 | 说明 |
|------|------------|------|
| 已有飞书的客户增购AI包 | ~40-50% | 取决于客户规模和行业 |
| 客户从竞品AI转向/叠加飞书AI | ~20-30% | 切换成本较高 |
| FDE首访后客户同意第二次会议 | ~60-70% | 正常跟进节奏 |
| 客户明确说"有预算"→实际签约 | ~50-60% | 预算可能被挪用 |
| 三方对齐会→产出规划书 | ~80-90% | 主要是自己内部执行 |
| 规划书→客户确认执行 | ~50-60% | 取决于方案匹配度 |

## 方法三：贝叶斯更新

### 核心公式（直觉版）

```
新概率 = 旧概率 × （新证据的支持程度）
```

每获得一条新信息，不推翻原有判断，而是**微调概率**。

### 操作步骤

1. **设定先验概率**（用外部视角打的底）
2. **收集新证据**（每次对话、每份文档）
3. **评估证据强度**：
   - 这条证据在多大程度上支持/反对我的假设？
   - 如果假设为真，这条证据出现的概率是？
   - 如果假设为假，这条证据出现的概率是？
4. **更新概率**

### FDE实战例子

**假设：** 捷安高科愿意试点飞书CRM
- 先验概率（基于参考类）：**40%**
- 新证据：白晓亮参加周四效率先锋大赛
  - 支持程度：中等（他来现场说明关注信息化建设）
  - 更新：40% → **50%**
- 新证据：白晓亮主动问你CRM方案
  - 支持程度：强（主动询问说明有真实需求）
  - 更新：50% → **70%**

### 贝叶斯更新速查

| 证据类型 | 更新幅度参考 | 举例 |
|---------|------------|------|
| 间接信息（文档、报告） | +-5% | 客户行业报告 |
| 中强度信号（邮件、群聊） | +-10% | 客户群里问了相关问题 |
| 直接信号（当面沟通） | +-15-20% | 客户当面说"我们有这个需求" |
| 强确认信号（决策者拍板） | +-25-30% | CEO说"这个方向可以" |
| 否定性证据 | 反向更新同幅度 | 客户说"预算已经花完了" |

## 方法四：Brier Score 度量体系

### Brier Score 公式

```
Brier Score = (预测概率 — 实际结果)²

实际结果：发生=1，未发生=0

完美预测：0
完全错误：1
随机猜测：0.5
```

### 两个维度

| 维度 | 含义 | 表现 |
|------|------|------|
| **校准度（Calibration）** | 概率是否准确 | 你说70%会发生的事，真的发生了70%吗？ |
| **区分度（Resolution）** | 敢不敢给极端值 | 你敢说90%或10%，还是永远在50%附近和稀泥？ |

### 你的FDE预测记分卡

建议每周/每月回顾一揽子预测，不要看单次对错。

**模板：**

| 项目 | 预测概率 | 结果(1/0) | Brier Score |
|------|---------|-----------|------------|
| 周四见白晓亮 | 80% | 1 | (0.8-1)²=0.04 |
| 白晓亮当面确认CRM需求 | 50% | ? | - |
| 牧唐本周内完成续费 | 30% | ? | - |
| 牧唐绩效原型周五前做完 | 90% | ? | - |
| **平均Brier Score** | - | - | **待计算** |

## FDE实战：三步预测工作流

每次面对客户决策时，走一遍这个流程：

### 第一步：费米化（5分钟）

- **云状问题** → 拆成可检验的子问题
- 例："这个客户能不能签？" → 
  - "第1次拜访后，客户是否同意第2次会议？（概率__%）"
  - "客户是否在2周内给出明确反馈？（概率__%）"

### 第二步：概率化（5分钟）

- 先找参考类（基础比率）
- 再用自己的特殊性微调
- 给每个子问题一个具体概率

### 第三步：贝叶斯更新（每次新信息后，1分钟）

- 旧概率 + 新证据的强度 = 新概率
- 用项目管理工作台的“项目任务”表记录每次概率更新

### 每周复盘（30分钟）

- 把预测结果填入记分卡
- 算本周的Brier Score
- 找校准度偏差（是不是过于乐观/悲观）
- 找区分度问题（是否不敢给极端值）

## 与泼冷水原则的结合

这是泼冷水原则的**科学化版本**：

| 泼冷水 | 超级预测法对应 |
|--------|--------------|
| "你最可能会崩在哪？" | 费米化 → 拆成具体的失败点 |
| "凭什么觉得能成？" | 外部视角 → 先看基础比率 |
| "你这假设验证了没？" | 贝叶斯更新 → 每次新信息微调概率 |
| "又拍脑袋？" | Brier Score → 用量化检验判断力 |
