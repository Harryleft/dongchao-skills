# 翻译 SKILL

三种翻译模式：**快速**直接翻译，**普通**先分析再翻译，**精细**完整出版级工作流（分析→翻译→审校→润色）。

## 核心理念

> **重写，而非翻译。** 用目标语言"重写"这段内容，而非逐句"翻译"。"翻译"让模型惦记原文每个字，"重写"给了它更大自由度去处理隐喻、重组句式。质量检验标准："这段译文读起来像是用目标语言原创写的吗？"

## 翻译模式

| 模式 | 步骤 | 何时使用 |
|------|------|---------|
| 快速 | 翻译 | 短文本、非正式内容、快速看大意 |
| 普通 | 分析 → 翻译 | 文章、博客、一般内容（默认） |
| 精细 | 分析 → 翻译 → 审校 → 润色 | 出版级、重要文档、需要精雕细琢 |

**默认模式：普通**。翻译完后提示用户可升级："翻译完成。如需进一步审校润色，回复'继续润色'。"

**自动检测：**
- "快翻"、"quick"、"直接翻译" → 快速模式
- "精翻"、"refined"、"publication quality" → 精细模式
- 其他 → 普通模式

## 识别源语言与目标语言

- 用户指定了 → 用用户指定的
- 未指定 → 默认规则：
  - 英文 → 中文（简体）
  - 其他语言 → 中文（简体）
  - 源语言已是中文 → 翻译为英文

## 翻译风格预设

| 风格 | 说明 |
|------|------|
| `storytelling`（默认） | 叙事流畅，引人入胜，自然过渡 |
| `formal` | 专业、结构化，无口语化表达 |
| `technical` | 精确、文档风格，术语密集 |
| `literal` | 贴近原文结构，最小重组 |
| `academic` | 学术、严谨，正式语体 |
| `business` | 简洁、结果导向 |
| `humorous` | 保留并适配幽默 |
| `conversational` | 随意、口语化 |
| `elegant` | 文学性、修辞精炼 |

## 目标读者预设

| 读者 | 效果 |
|------|------|
| `general`（默认） | 通俗语言，专业术语加译注 |
| `technical` | 技术读者，少解释常见术语 |
| `academic` | 学术读者，正式语体 |
| `business` | 商务人士，通俗解释技术概念 |

## 翻译原则（所有模式通用）

1. **重写而非翻译**：用目标语言自然重写，不是逐句翻译。每句话读起来应该像母语者原创的。
2. **准确优先**：事实、数据、逻辑必须与原文完全一致。
3. **自然流畅**：使用目标语言地道的语序。长句拆短句。隐喻和惯用语按意图含义翻译，而非字面直译。
4. **术语一致**：术语表中的翻译全文统一。专业术语首次出现时附原文括号注释。
5. **格式保留**：保留所有 Markdown 格式（标题、加粗、斜体、图片、链接、代码块、Callout、Mermaid 等）。
6. **主动译注**：对目标读者可能缺少背景知识的概念，加简洁译注 `（**解释**）`。仅加真正需要的。

## 术语处理规则

| 类别 | 规则 | 示例 |
|------|------|------|
| 人名 | 英文人名保留英文，首次附中文译名 | Garry Tan（加里·谭） |
| 公司/产品名 | 保留英文原名 | OpenAI, Anthropic, Y Combinator |
| 技术术语 | 保留英文，首次附中文解释 | FDE（Forward Deployed Engineer，前置部署工程师） |
| 易误译术语 | 使用术语表统一翻译 | Moat → 护城河, Hallucination → 幻觉 |
| 代码/命令 | 完全保留，不翻译 | `skillify`, `/skillify` |

## 工作流

### 快速模式

直接翻译 → 保存。应用所有翻译原则，但跳过分析和审校。

### 普通模式

#### Step 1：内容分析

翻译前先分析源内容：

1. **内容摘要**：核心论点、作者背景、写作目的
2. **术语提取**：专业术语、专有名词、品牌名、缩写 → 确定翻译
3. **语气风格**：正式/随意？幽默/隐喻/文化引用？
4. **翻译难点**：
   - 理解障碍：目标读者可能不懂的概念
   - 隐喻语言：隐喻、惯用语 → 按意图翻译，非字面
   - 结构挑战：长复合句、双关、幽默

#### Step 2：翻译

基于分析结果翻译全文。应用翻译原则 + 术语表 + 分析中识别的难点处理策略。

#### Step 3：升级提示

翻译完成后提示：
> 翻译完成。如需进一步审校润色，回复"继续润色"。

### 精细模式

完整出版级工作流：

#### Step 1：内容分析（同普通模式，更深入）

额外关注：隐喻映射（每个隐喻的作者意图、直译风险、目标语言处理策略）、情感色彩保留。

#### Step 2：初稿翻译

基于分析翻译全文，保存初稿。

#### Step 3：审校（诊断，不修改）

对初稿进行严格审校：

**3.1 准确性**
- 逐段对照原文
- 核实事实、数字、日期、专有名词
- 标记误增、误删、误改的内容

**3.2 地道性**
- 标记读起来像"翻译过来的"句子——不自然语序、硬译、生硬表达
- 中文目标：检查不必要连接词（因此/然而/此外）、被动语态滥用（被/由/受到）、名词堆砌
- 标记直译的隐喻（在目标语言中不自然）
- 检查情感色彩是否被扁平化

**3.3 译注与适配**
- 译注是否准确、简洁、有用？
- 是否遗漏需要译注的概念？
- 翻译策略是否按分析执行？

#### Step 4：修订

根据审校发现修订全文：修正准确性问题、重写不自然表达、调整译注、改善流畅度。

#### Step 5：润色

最终润色：
- 通读全文，读起来像是目标语言原创的吗？
- 打磨粗糙过渡
- 确保叙事声音和风格全文一致
- 最终术语一致性检查
- 验证格式正确保留

## 翻译错误处理与降级策略

### 模型输出异常

| 异常 | 检测方式 | 处理 |
|------|----------|------|
| 输出不完整 | 末尾断句、段落未闭合 | 重试，提示"请输出完整翻译" |
| 格式丢失 | 原文有 Markdown 格式但译文无 | 重新翻译，强调"必须保留所有格式标记" |
| 术语表冲突 | 同一术语出现两种译法 | 以术语表为准，全局替换为术语表版本 |
| 语言混淆 | 译文中混入源语言句子 | 标记问题段落，重新翻译该段 |
| 重复/遗漏段落 | 译文段落数 ≠ 原文段落数 | 逐段对照，补漏删重 |

### 分块翻译失败恢复

- 单块失败：重试该块 1 次，仍失败则跳过并标记 `⚠️ 第 N 块翻译失败，请手动检查`
- 多块失败（>50%）：中止分块翻译，改为全文一次性翻译（牺牲质量换完整性）
- 合并时发现块间矛盾：以后一块为准（更接近最终上下文），在译注中标明

## 长内容分块翻译

当内容超过 ~4000 词时：

1. **先提取术语**：扫描全文提取专业术语、专有名词、反复出现的短语
2. **建立会话术语表**：合并提取的术语 + 内置术语表，确定统一翻译
3. **按 Markdown 结构分块**：在 Markdown 块边界切分（标题后、段落边界），不切断表格、代码块、列表
4. **共享上下文翻译**：每个块使用相同的术语表 + 翻译原则 + 分析结果，确保一致性
5. **合并后通读**：块间衔接处重点检查术语一致性和叙事连贯

### 分块切分规则

- **阈值：** 按 token 计算而非词数。每块不超过 3000 token（约 2000 中文词）。用 `len(text) / 3` 粗估 token 数（中文 1 字 ≈ 1-2 token）
- **切分点：** 优先在 `##` / `###` 标题后切分，其次在空行（段落边界）切分
- **禁止切分：** 代码块内、表格行之间、列表项之间
- **上下文重叠：** 每块开头包含前一块的最后 200 词作为上下文锚点，用 `---` 分隔，翻译时参考但不输出这部分

### 合并后通读检查清单

- [ ] 块间术语一致（同一术语全文统一译法）
- [ ] 块间衔接自然（无突兀转折、重复主语）
- [ ] 人名/地名拼写一致
- [ ] 无遗漏段落
- [ ] 格式标签完整（无孤立的 `**` 或 `](` ）

## 分块原则

- **在结构安全处切割**：段落边界、标题之后
- **不切断代码块、表格、列表**
- **每个块保留足够的上下文**：包含前一块的最后一段作为上下文参考

## 反模式

| 反模式 | 为什么不行 |
|--------|-----------|
| 逐字直译 | 读起来不像人话 |
| 技术术语强行中文化 | PMF 翻成"产品市场适应度"不如保留 PMF |
| 漏译段落 | 信息丢失 |
| 添加原文没有的修饰 | 翻译不是改写 |
| 翻译代码块 | 代码不可翻译 |
| 隐喻字面直译 | "从后视镜里看"是英文隐喻，中文读者别扭 |
| 情感扁平化 | "alarming"不只"惊人的"，还有"不安" |
| 过度译注 | 模型已知的常见术语不用加注 |

## 自定义术语表

用户可提供自定义术语表来覆盖内置翻译。术语表存放在 `~/workspace/agent/plugin-skills/miaoda-translate/glossary.md`。

### 文件格式

```markdown
# 自定义术语表

| English | Chinese | Notes |
|---------|---------|-------|
| My Term | 我的译法 | 仅在此项目中使用 |
```

### 加载规则

1. 翻译前自动读取 `glossary.md`（如存在）
2. 与内置术语表合并
3. **冲突时自定义优先**：自定义术语表覆盖内置术语
4. 会话术语表（从当前文档提取）优先级最高

### 优先级（高→低）

```
会话术语表（当前文档提取） > 自定义术语表（glossary.md） > 内置术语表
```
