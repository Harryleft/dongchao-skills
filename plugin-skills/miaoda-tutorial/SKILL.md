# FDE 教程生成技能

为 FDE 定制的教程生成器。核心差异：**不是通用教程，而是面向客户交付和新人培训的落地指南。**

## FDE 场景适配

原版 yao-tutorial-skill 是通用教程生成器。本技能做了以下 FDE 特化：

| 维度 | 原版 | FDE 版 |
|------|------|--------|
| 受众 | 通用初学者 | 客户决策者/业务人员、FDE 新人 |
| 目标 | 知识传递 | **场景落地+赋能+消耗驱动** |
| 深度 | 学习充分性 | **能照做、能复现、能自检** |
| 证据来源 | 学术论文+官方文档 | **行业案例+飞书产品文档+客户业务数据** |
| 输出格式 | PDF/Word/HTML | **飞书云文档优先**，PDF/HTML 辅助 |
| 可视化 | 通用配图 | **飞书 AI 产品截图+架构图+流程图** |
| 时间预算 | 无限 | **单份教程 ≤ 2 小时产出** |

## FDE 教程类型速查

| 教程类型 | 触发词 | 深度 | 典型场景 |
|---------|--------|------|---------|
| **落地指南** | "落地指南""实施手册" | 深（6-10章） | 客户首次部署 AI 场景 |
| **培训手册** | "培训手册""培训材料" | 中（4-6章） | 客户赋能培训、FDE 新人培训 |
| **快速上手** | "快速上手""入门指南" | 浅（3-4章） | 5 分钟快速演示、单一功能指引 |
| **方案说明** | "方案说明""场景方案" | 中（4-8章） | AI 场景落地规划书、招投标方案 |

## 妙记（飞书分钟）→ 教程 转换流程

**触发条件：** 用户提供飞书妙记链接（`https://xxx.feishu.cn/minutes/obcnXXXX`）并要求生成教程。

**完整链路：**

```
妙记 URL → 提取 minute_token → vc +notes 获取逐字稿/总结/章节
         → 用逐字稿做用户资料（must_use）
         → 走 miaoda-tutorial 标准流程
         → 输出飞书云文档教程
```

### Step A：提取 minute_token

从妙记 URL 末尾提取：
```
https://xxx.feishu.cn/minutes/obcnXXXX?xxx → minute_token = obcnXXXX
```

### Step B：获取妙记元信息

```bash
lark-cli minutes minutes get --params '{"minute_token":"obcnXXXX"}'
```

获取：标题、时长、所有者。用于 Brief 的 topic 和 audience 判断。

### Step C：获取逐字稿和 AI 产物

```bash
# 获取纪要产物（总结、待办、章节、逐字稿）
lark-cli vc +notes --minute-tokens obcnXXXX
```

返回包含：
- `note_doc_token` — AI 智能纪要（总结 + 待办 + 章节）
- `verbatim_doc_token` — 逐字稿（完整对话记录，含说话人和时间戳）

**读取内容：**
```bash
# 读取 AI 纪要内容（总结+章节）
lark-cli docs +fetch --api-version v2 --doc <note_doc_token> --doc-format markdown

# 读取逐字稿内容
lark-cli docs +fetch --api-version v2 --doc <verbatim_doc_token> --doc-format markdown
```

### Step D：将逐字稿作为 must_use 资料输入 miaoda-tutorial

- 逐字稿 → `must_use`（教程必须基于视频实际内容）
- AI 总结 → `supporting`（参考结构，但教程要重新组织）
- AI 章节 → 参考但不照搬（教程章节应按学习者路径设计，不是按视频时间线）

**关键原则：** 教程 ≠ 视频逐字稿的重新排版。教程要从视频内容中提取可学习的知识点，按学习者路径重新组织。视频是原材料，不是骨架。

### Step E：走 miaoda-tutorial 标准流程

从 Step 0 开始，Brief 中：
- `topic` = 妙记标题
- `user_materials.must_use` = 逐字稿内容
- `user_materials.sufficiency_tier` = "rich"（逐字稿通常很充分）

### 错误处理

| 错误场景 | 处理方式 |
|---------|----------|
| minute_token 提取失败 | 提示用户确认妙记链接格式 |
| vc +notes 返回无纪要 | 视频可能未生成纪要，提示用户先在飞书中打开妙记等待 AI 处理 |
| 逐字稿内容为空 | 用 AI 总结作为 must_use，逐字稿标记为 unavailable |
| 逐字稿过长（>50000词） | 截取关键章节，标注「基于视频前 N 分钟」 |
| 无权限访问妙记 | 提示用户确认妙记共享权限 |

## 完整工作流

### Step 0：需求分类（FDE 特有）

收到教程需求后，先判断类型：

```
用户需求
  │
  ├─ 客户要培训？ → 培训手册
  ├─ 客户要落地？ → 落地指南
  ├─ 快速演示用？ → 快速上手
  ├─ 投标/规划书？ → 方案说明
  └─ 其他？ → 按"培训手册"默认
```

**必问信息（缺任何一个就问）：**
- 目标受众（客户业务人员？IT？管理层？FDE 新人？）
- 核心产品（多维表格？aily？妙搭？）
- 行业背景（制造？零售？医疗？）
- 参考资料有无

### Step 1：Brief 规范化

将需求标准化为 Brief JSON。使用 `templates/topic-brief-template.json` 作为模板，填写 FDE 扩展字段。

**FDE Brief 扩展字段：**

```json
{
  "topic": "主题",
  "audience": "客户业务人员",
  "audience_level": "零基础/有基础/高级",
  "outcome": "学完后能做什么",
  "product": "飞书多维表格/aily/妙搭",
  "industry": "制造业/零售/医疗/...",
  "tutorial_type": "落地指南/培训手册/快速上手/方案说明",
  "language": "zh-CN",
  "formats": ["feishu_doc", "pdf"],
  "user_material": [],
  "time_budget": "2h",
  "exclusions": []
}
```

### Step 2：资料适配

用「核心决策逻辑」中的资料适配决策表判断用户资料充分度，选择研究策略。

冲突处理：用户资料与外部证据矛盾时 → 保留用户意图，事实部分用更强来源，在教程中简要说明限制。

### Step 3：研究采集

用「核心决策逻辑」中的研究采集规则执行。来源按 FDE 优先序：客户数据 > gbrain 案例 > 飞书产品文档 > web_search。

每条研究记录包含：`| id | type | title | source | use_for | key_takeaway | status |`，状态标注：已验证 / 路演阶段 / 概念阶段 / 未验证。

### Step 4：大纲+写作

用「核心决策逻辑」中的大纲设计规则和章节节奏执行。

**FDE 大纲模板（按类型）：**

#### 落地指南大纲
```
第1章：业务痛点与 AI 机会（为什么需要）
第2章：方案全景图（整体怎么解决）
第3章：环境准备与账号配置（动手前准备）
第4章：核心场景搭建（手把手做）
第5章：进阶场景与自动化（深入使用）
第6章：数据看板与效果衡量（怎么评估）
第7章：常见问题与排障（出问题怎么办）
第8章：下一步行动清单（落地后做什么）
```

#### 培训手册大纲
```
第1章：5分钟理解核心概念
第2章：跟做第一个场景
第3章：独立完成标准流程
第4章：常见问题自助解决
附录：快捷键/常用操作/术语表
```

#### 快速上手大纲
```
第1章：一分钟了解是什么
第2章：三步完成首次操作
第3章：进阶技巧与推荐
```

#### 方案说明大纲
```
第1章：行业背景与痛点分析
第2章：AI 解决方案架构
第3章：场景一：XXX
第4章：场景二：XXX
第5章：场景三：XXX
第6章：实施路径与里程碑
第7章：效果评估与 ROI
```

**FDE 写作约束：**
- 每个操作步骤必须可截图证明（方便后续补充产品截图）
- 禁止使用"简单地点击"等模糊表述——写出具体的菜单位径：`飞书 → 工作台 → 多维表格 → 新建`
- 每章末尾必须有「本章行动项」——读者读完能立即做什么
- 客户案例用真实行业名（"某汽车制造企业"），不用"某大厂"

### Step 5：可视化

用「核心决策逻辑」中的可视化规则执行。

**FDE 可视化规则：**
- 流程图用 Mermaid（飞书文档原生支持）
- 架构图用 `<image>` 嵌入（优先用飞书产品截图）
- 数据对比用表格
- 关键操作用 callout 高亮
- **禁止：** 假的产品截图——要么用真实截图，要么用文字描述占位

**飞书文档视觉增强：**

| 内容类型 | 增强方式 |
|---------|---------|
| 操作步骤 | 编号列表 + callout 提示 |
| 架构说明 | Mermaid 流程图 |
| 数据对比 | 表格 |
| 关键警告 | ❌ callout（light-red） |
| 成功案例 | 💡 callout（light-blue） |
| 行动项 | ✅ callout（light-green） |

### Step 6：飞书云文档输出

用「核心决策逻辑」中的导出规则执行。优先 feishu_create_doc，长文档分段 append。

### Step 7：质量验证

**FDE 质量门禁（在原版基础上增强）：**

原版 7 项全部保留，追加 FDE 专项：

- [ ] **落地可执行性**：读者能否按教程独立完成场景搭建？（不是"理解概念"，是"照着做"）
- [ ] **产品准确性**：飞书产品的操作路径是否与当前版本一致？
- [ ] **行业适配性**：案例和话术是否匹配目标行业？
- [ ] **消耗关联性**：教程是否引导用户深入使用 AI 功能（驱动消耗）？
- [ ] **行动项可追踪**：每章行动项是否具体到"做什么、在哪做、怎么做"？

## 交付定义（Definition of Done）

教程「完成」的标准——以下 **全部满足** 才能交付：

| # | 标准 | 验证方式 |
|---|------|----------|
| 1 | FDE 5 项质量门禁全 ✅ | 逐项检查清单 |
| 2 | 每章有独立质量审核记录 | research/chapter-quality-review.md 存在且无 revise 状态 |
| 3 | 飞书云文档可正常打开 | 返回文档链接 |
| 4 | 操作步骤可截图证明 | 每个操作步骤有具体菜单位径 |
| 5 | 目标受众能照做 | 抽查 1 章，验证无隐藏前置知识 |

**允许带 KNOWN_GAPS 交付：** 如果 ≤2 项质量门禁未通过但非关键（如「消耗关联性」弱），可以交付但必须在文档末尾附 KNOWN_GAPS 清单，说明哪些项未通过、为什么、建议何时修复。

**不允许交付：** 如果 >2 项未通过，或「落地可执行性」「产品准确性」任一未通过。

## 修订循环

教程不是一次性产出。客户反馈后的修订流程：

```
交付初版 → 客户反馈 → 分类处理 → 修订 → 重新验证 → 更新文档
```

**反馈分类：**

| 反馈类型 | 示例 | 处理方式 |
|---------|------|----------|
| 事实错误 | "第3章的操作路径已经变了" | 立即修正，重新验证产品准确性 |
| 深度不足 | "这章太粗了，看不懂" | 补充示例、操作步骤、常见陷阱 |
| 内容多余 | "这章我们用不上" | 标记为可选/延伸阅读，不删除 |
| 需求新增 | "能不能加审批流章节" | 评估同文档追加 vs 另起文档 |
| 风格问题 | "太技术了" | 用场景+旧方法失败+新方案节奏重写 |

**修订后必须重新跑对应章节的质量审核**，更新 chapter-quality-review.md。不需要全书重审，只审修改的章节。

**feishu_update_doc 策略：** 修订时用 `replace_range` 模式 + `selection_by_title` 定位章节标题替换，不要整文档覆写。

## 失败模式与恢复

| 失败场景 | 检测方式 | 恢复策略 |
|---------|----------|----------|
| feishu_create_doc 失败 | 工具返回 error | 重试 1 次；仍失败则输出 Markdown 文件到本地，告知用户手动创建文档后用 feishu_update_doc 追加 |
| gbrain 无搜索结果 | search 返回空 | 降级为 web_search 补充；标注来源为「网络搜索，未验证」 |
| 飞书产品文档搜索无果 | search_doc_wiki 返回空 | 用 web_search 搜索飞书帮助中心；标注「可能非最新版本」 |
| 用户需求矛盾（如"零基础"但要求"深入架构"）| Brief 分析时发现 | 向用户确认优先级；默认按受众水平决定深度，矛盾部分放入「延伸阅读」 |
| 研究资料不足（thin packet）| 用户只给主题无资料 | 启动完整研究流程：web_search + gbrain + 飞书文档；每章标注「待验证」 |
| 时间预算超限 | 单章写作超 15 分钟 | 降级策略：当前章节压缩为「核心步骤+扩展阅读」结构，后续章节同理 |
| 质量门禁未通过 | FDE 专项检查有 ❌ | 记录未通过项到 `research/chapter-quality-review.md`，输出时附 KNOWN_GAPS 清单 |
| 内容过长（>30000 词）| 字数统计超限 | 分段创建飞书文档：首段 create，后续 append；每 5000 词一段 |

| 反模式 | 为什么不行 |
|--------|-----------|
| 写成产品说明书 | 客户不需要知道所有功能，需要知道"解决我的问题用哪些" |
| 操作步骤太粗 | "配置多维表格"不够，必须写"多维表格 → 添加字段 → 类型选单选 → 选项填 XX" |
| 用"某大厂"做案例 | 客户不信服。用行业+规模+具体场景："某 500 人汽车零部件厂" |
| 跳过环境准备 | 客户第一步就卡在权限/账号上，后面的全白写 |
| 没有排障章节 | 客户一定会遇到问题，没有排障 = 电话不断 |
| 通用化写法 | "适用于所有行业"= "对任何行业都不够深入"。选定一个行业深挖 |

## 时间预算

| 教程类型 | 预计产出时间 | 建议章节数 |
|---------|------------|-----------|
| 快速上手 | 15-30 min | 3-4 章 |
| 培训手册 | 1-2 h | 4-6 章 |
| 方案说明 | 2-3 h | 5-8 章 |
| 落地指南 | 2-4 h | 6-10 章 |

超时保护：如果单章写作超过 15 分钟，降级为"核心步骤 + 扩展阅读"结构。

## 核心决策逻辑（内联，无需读 reference 文件）

以下是 8 个 reference 文件的关键决策规则摘要。需要深入时再读对应文件。

### 资料适配决策（来自 input-adaptation.md）

| 用户资料充分度 | 判断标准 | 研究策略 |
|--------------|----------|----------|
| **丰富** | 有完整草稿/5+URL/明确必须用案例 | 用户资料做脊梁，补 3-8 条外部验证 |
| **中等** | 有主题+少量笔记，角度清晰但不完整 | 保留用户角度，补 6-12 条外部素材 |
| **薄弱** | 只有主题或一段话 | 完整研究流程，目标 10-18 条外部素材 |

**冲突处理：** 用户资料与外部证据矛盾时 → 保留用户意图，事实部分用更强来源，在教程中简要说明限制。

### 研究采集规则（来自 research-sourcing.md）

来源层级（FDE 优先序）：
1. 客户提供的业务数据和流程文档
2. gbrain 中的同行业已落地案例（标注落地状态）
3. 飞书产品文档（feishu_search_doc_wiki）
4. web_search 外部行业研究

每条研究记录包含：`| id | type | title | source | use_for | key_takeaway | status |`
状态标注：`已验证 / 路演阶段 / 概念阶段 / 未验证`

### 大纲设计规则（来自 tutorial-outline-and-writing.md + course-design-principles.md）

**大纲公式：** `大纲条目 = 专业内容 + 学习者痛点/期望结果`

**点线面体系：**
- 点：列出知识点、用户问题、痛点、案例、术语、常见错误
- 线：将相关点合并为章节问题
- 面：按逻辑分组（流程/因果/对比/分类）
- 体系：章节形成连贯方法论，不是技巧堆砌

**每章必须包含：**
- 章节目标 + 通俗概念 + 章节配图
- 一个引导性示例或演练
- 「注意」callout + 常见陷阱
- 实践任务 + 检查点问题

**章节节奏：** 场景挑战 → 旧方法失败 → 新方案 → 新结果

**终止条件：** 学习充分性——学习者能理解、应用、自查，而非固定字数。

### 可视化规则（来自 visual-board-benchmarks.md + visual-html-workflow.md）

- 每章至少一个可视化
- 流程/架构 → Mermaid
- 对比 → 表格
- 关键操作 → callout
- 禁止假截图，用文字占位符

### 导出规则（来自 export-workflow.md）

- **飞书云文档优先**：feishu_create_doc + feishu_update_doc append
- 长文档分段：每 5000 词一段 append
- HTML 导出用 templates/tutorial-style.css
